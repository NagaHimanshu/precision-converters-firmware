# Gallery (guest photo sharing) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the "coming soon" Gallery with guest photo sharing: browse, heart, upload
(resized on the phone), "Photos by me" + delete, optional Google sign-in, pause switch,
Drive-full handling — all failure-contained so nothing else on the site can break.

**Architecture:** A lazily loaded gallery module (`public/gallery/*.js` + css, one global
namespace `self.WeddingGallery`) mounted by `app.js` inside a try/catch wall. It talks to a
Google Apps Script web app (`apps-script/*.gs`) that stores photos in a Drive folder and
records/hearts/owners in a private spreadsheet. On this PC the backend is replaced by a
Python stand-in (`tools/dev_server.py`) implementing the same contract with failure modes.

**Tech Stack:** Plain ES2020 JS/CSS/HTML (no build, no deps), Google Apps Script (V8),
Google Identity Services, Python 3.10 + Pillow (dev tooling only), headless Chrome for tests.

**Spec:** `docs/superpowers/specs/2026-11-09-gallery-design.md` (mockup:
`docs/superpowers/specs/2026-11-09-gallery-mockup-v3.html`). Read both before any task.

## Global Constraints

- No git on this PC: **no commit steps**. Task 1 makes a zip backup; never delete a file
  without one. Never run firebase/Google commands here.
- No hard-coded content or limits: every number, limit, URL template and string lives in
  `public/site-config.js` (public) or `apps-script/Config.gs` (private). Private values
  (owner email, folder/sheet IDs, secrets) never go in `site-config.js`.
- No browser-specific code: never branch on user agent / platform / in-app browser.
  Handle failures by their failure.
- Match `app.js` style: IIFE, `"use strict"`, the `h()` element helper, text via config,
  short comments. All guest-visible strings from `CFG.text.gallery`. Never use
  `innerHTML` with data; names and any server text go in via text nodes only.
- Elder-friendly: body text ≥ 18px; tap targets ≥ 44px; destructive actions confirmed;
  every gesture has a button alternative (arrows in viewer).
- Gallery code must not load until the Gallery screen is opened; Google's GIS script
  loads only when a sign-in control is shown.
- Nothing may spin forever: every network call has a timeout; every failed thing offers
  Try again; guests never see raw errors/codes (console only).
- Docs updated in the task that changes the behaviour they describe; final doc pass in
  Task 10.
- Owner email: not written anywhere. `OWNER_EMAIL` in `apps-script/Config.gs` stays blank = the account the script runs under (owner request).

## Shared contract (site ↔ backend ↔ stand-in)

Every request: `POST {gallery.endpoint}` with header `Content-Type: text/plain;charset=utf-8`
(no preflight — Apps Script can't answer one) and body = JSON string. Every response is JSON.
Success: `{ "ok": true, ... }`. Failure: `{ "ok": false, "code": <Code> }`.

`Code` = `"busy" | "unavailable" | "full" | "paused" | "invalid" | "forbidden" |
"too_large" | "rate_limited" | "signin_failed"`.

`Photo` = `{ id: string /* Drive file id */, by: string /* "" = anonymous */,
at: number /* ms epoch */, hearts: number, hearted: boolean, mine: boolean }`

| action | request fields (besides `action`, `device`) | success fields |
|---|---|---|
| `list` | `cursor?: string`, `limit: number`, `mine?: boolean` | `photos: Photo[]` (newest first), `next: string \| null`, `total: number`, `uploadsOpen: boolean`, `full: boolean`, `account: {name} \| null` |
| `upload` | `name: string`, `mime: "image/jpeg"`, `data: string` (base64, no prefix) | `photo: Photo` |
| `heart` | `id`, `on: boolean` | `hearts: number`, `hearted: boolean` |
| `delete` | `id` | — |
| `link` | `idToken: string` | `account: {name}`, `linked: number` |
| `unlink` | — | — |

`device` = the phone's secret code (string, 32 hex chars). A device linked via `link`
counts as its Google account for every later request (so the Google ID token is only sent
once per phone; no token renewal needed). `total` counts the listed tab.

## Review Focus

1. 20 large photos picked on an older iPhone → page must not run out of memory: at most
   one photo is being decoded/resized at any moment (Task 6 test
   `uploader prepares one photo at a time`).
2. The backend answers with an HTML page (Google sign-in/error page after a bad
   deployment setting) or a 500 → "temporarily unavailable" card, never a parse crash
   (Task 3 tests `html response maps to unavailable`, `http 500 maps to unavailable`).
3. A guest taps a heart several times quickly or while offline → final shown state = last
   tap, count never negative, sent once state settles (Task 4 test
   `rapid heart taps settle on last state`).
4. A name containing markup (`<img src=x onerror=alert(1)>`) or 300 characters or
   control characters → shown as plain text, trimmed to `nameMaxLength`
   (Task 4 test `names render as text`; Task 5 test `cleanName`).
5. Guest leaves the Gallery or presses Back mid-upload / with the viewer open → uploads
   keep going; Back closes the viewer without leaving the Gallery (Task 6 test
   `hide does not cancel uploads`; Task 4 test `back closes viewer`).

### Task 3: Backend client (`api.js`) + stand-in list/heart

**Files:**
- Create: `public/gallery/api.js`, `tests/api.test.js`
- Modify: `tools/mock_gallery.py`, `public/app.js` (`GALLERY_FILES`)

**Interfaces:**
- Consumes: `GalleryError` (Task 2).
- Produces: `WeddingGallery.api.create({ endpoint, requestTimeoutMs, uploadTimeoutMs,
  retries, retryBackoffMs, fetchImpl? = fetch }) -> { call(action: string, payload: object,
  opts?: { timeoutMs?: number, retries?: number }) -> Promise<object /* ok:true body */> }`
  Rejects only with `GalleryError`. Mapping:
  - network `TypeError` → `offline` if `navigator.onLine === false`, else `unavailable`
  - timeout (AbortController) → `unavailable`
  - HTTP status not 2xx, or body not JSON, or JSON without boolean `ok` → `unavailable`
  - `{ok:false, code}` → that code if it is a known `Code`, else `unavailable`
  - retry (with `retryBackoffMs * 2^attempt`) only for `busy`, `unavailable`, `offline`,
    up to `retries`; never retry `upload` after a timeout unless `opts.retries` says so.
- Stand-in (`mock_gallery.py`): in-memory store seeded with 45 photos (Pillow-generated
  solid-gradient JPEGs, varied aspect ratios, `by` mix of names and ""), hearts per
  device; implements `list` (cursor = opaque offset string, `mine` filter by device),
  `heart`; `handle_img` serves the photo resized to `w`. Modes from `?mode=`:
  `ok`, `empty` (no photos), `down` (HTTP 500 + HTML), `html` (200 + HTML page),
  `slow` (sleep 20 s), `busy` (first 2 calls per device `busy`, then normal),
  `full` (list `full:true`; upload → `full`), `paused` (list `uploadsOpen:false`; upload →
  `paused`), `badthumbs` (every 3rd image 404). Requests must have
  `Content-Type: text/plain` else 400 (keeps the client honest about preflight).

- Produces — `WeddingGallery.store.create({ api, identity, cfg, storageGet, storageSet }) -> Store`:
  - `state` (read-only snapshot): `{ tab: "all"|"mine", photos: Photo[], total: number,
    next: string|null, status: "idle"|"loading"|"ready"|"error", error: Code|null,

    successful `load`/`refresh`. Count = server count adjusted by ±1 for unsent changes,
